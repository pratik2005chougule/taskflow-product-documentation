# Contributing to this portfolio project

This is a self-initiated documentation sample for learning and portfolio development.

## Suggested workflow

1. Create a GitHub issue describing the documentation change.
2. Create a branch using a descriptive name, such as `docs/add-task-filters`.
3. Update the relevant Markdown page.
4. Preview the Markdown locally.
5. Commit with a clear message, such as `docs: clarify task status workflow`.
6. Open a pull request and describe the change.
7. Review the rendered content before merging.

## Documentation review checklist

- Is the intended audience clear?
- Does the page start with the user's goal?
- Are procedures written as numbered steps?
- Are UI labels consistent?
- Are API methods, paths, parameters, and examples consistent?
- Are links valid?
- Are examples clearly identified as illustrative?
